## 核心觀點

没有员工，没有外包，成本只有一个 Codex 订阅、一个 Claude 订阅，再加一点点 API 费用。

现在外网上到处都是"AI + Google Map，40秒变现"的短视频，大部分最后都在推某个一键建站工具。这门生意是真的，但"一键赚钱"的幻想不是。和我真正做了几个月之后看到的，完全是两回事。

我不打算通过任何免费或收费的方式分享出整套工作流，但是会讲讲整个跑通的过程，如果你精通ai却苦于变现；或者和我曾经一样，不想上班却对未来感到迷茫，看完这篇可能会有一点点收获。

## 1. 从头说起

今年春节期间我在家闲着，正好赶上 OpenClaw 大火。对我这样一个没有技术背景、但好奇心足够重的设计从业者来说，这更像是一个信号：很多过去光是起步就得请工程师的事，忽然之间近到了一个新手也能上手的程度。

当时脑子里一直在转一个问题：以今天ai的水平，它到底能把什么做到让一个真实的生意愿意掏钱？

我的判断是，正经的软件还差得远。一旦你需要一个产品被上线、被维护、被信任、被真实客户每天使用，AI 就会出问题。但做demo、落地页、对设计没有极高要求的小网站，它似乎能够满足需求。

我是个设计师，以前vibecoding过网站，也做过一些小软件，这意味着我看一眼 AI 的产出，就能立刻分辨哪个版本能用、哪个版本拿不出手。这听起来是个很小的技能，结果它就是整个生意。

对普通人来说，AI 时代的机会，就存在于个人能力上限和 AI 能力的边界重叠的地方。

我的重合部分：local商家网站。这种网站不需要生产级的工程能力，但需要审美、内容，以及一个真的能把它部署上线、再把它卖出去的人。

基于在英国的生活经验，我很快想到了欧洲小餐馆的网站：中国的餐饮和本地服务，基本都被装进了微信或者大众点评这种第三方平台里；而在英国乃至欧美，没有一个把一切聚合起来的超级平台。一家小店的独立官网，到今天仍然是它身份和宣传的一部分。这种网站不需要生产级的工程，也不需要拿奖级别的设计，但它得有现代的审美、清爽的排版，还得有足够稳定的功能，容易维护

## 2.从哪里开始

我做的第一个真正的决策，是决定不去哪里找。

从直觉出发，伦敦是最顺理成章的选择，但我恰恰跳过了它。伦敦餐厅的网站大多已经比较成熟了。那些没有网站、或者网站很烂的，往往靠着本地口碑照样过得不错。这有点像国内那些出了名的苍蝇馆子，这种店我帮不上太多忙，他们通常也不需要。

所以我转向了旅游小镇，比如 Blackpool、Bath、Lake District。这些地方不一定最富裕，但游客很多。一个游客到了镇上，打开谷歌地图，比较几家餐厅，看看菜单和照片，然后挑一家——就跟我们用大众点评挑店差不多。对旅游小镇的餐厅来说，网站往往就是它的门面。

## 3.第一个客户

第一个客户是 Blackpool 的一家意大利餐厅。

他们的问题蠢得离谱：他们有Wix（国外常见的自助建站平台）搭的网站，电脑上打开没问题，但手机上打不开，因为Wix的手机端需要进行独立适配。这就导致老板以为自己有网站，与此同时，每一个站在海滨大道上搜"italian restaurant near me"的游客，打开的都是一个死页面。

那个阶段我还在一家一家手动检查商家。后来我把这些筛选策略写成了自动化脚本。这单以 600镑成交，因为是第一单所以报价报低了。实际交付的内容放到现在我会收1200英镑，但没什么可惋惜的，在起步的阶段，证明这条路走得通，比多挣几百块要重要得多。

## 4.弯路

我最初的计划就是你能猜到的那种：在Google Map上找商家，让AI写cold email，批量发送，等回复。

我连发了三四天。没有任何回音。

这些邮件的毛病很典型：长、客气、且空泛，"请问您需要网站搭建或维护服务吗？" 这种邮件，每个老板都删过无数封。

这时作为中国人的好处就是：我们的互联网上有太多赚老外钱的经验了。外贸行业已经把这件事打磨了几十年，总结出来的核心打发就是：客户必须感觉到你了解「他」，感觉到你在做他的生意前花了心思。一条通用的模版消息，不会因为群发给更多人就有效果。

于是我把整个打法反了过来：联系更少的商家，但在开口之前，先给每一家做一个定制 demo，用他们真实的信息、真实的菜单、真实的评价、真实的照片。如果他们的照片很差（通常是快餐店），我就用 AI 生成更接近专业摄影的图片。关键在于图片不能一眼就有“ai味儿”，这一点对小店老板的杀伤力特别大。

当时我花了很多时间去调 Midjourney 的提示词，才把这个效果磨出来；现在有了gpt的Image2，这件事轻松多了。当老板打开链接，看到自己的店出现在屏幕上，带着他的名字、他的菜单，呈现出连他都未曾设想的精致感时，主动权就在我们手上了。

## 5.现在的工作流什么样

![Image](https://pbs.twimg.com/media/HPl6fOVawAAyaEN?format=jpg&name=900x900)

[X.com media](https://x.com/haoran_tang97/article/2087829572930633771/media/2087834579105398784)

现在的前期流程分四层：screening/production/depoly/contact。一个主 agent 负责分派任务，审核所有返回的结果并进行飞轮进化；一个筛选agent负责选定城市、按我的标准扫描商家并打分。打完分之后，我还会亲手再过一遍，只有少数几个通过人工筛选的，才会进入更深入的信息抓取和 demo 制作。

人工这一步之所以重要，是因为真正的购买信号并不是纯技术性的。我要判断的是：能不能联系上、经营者够不够认真、有没有充足的预算，以及对方是不是那种会为一个像样网站感到骄傲的老板。这些判断来自我在西方国家生活的经验，一种“感觉”，是整套流程里最难被自动化的一环，可能也是最有价值的一环。

关于模型的选择：我现在用的是一套基于 Hermes 的GPT+Claude架构。早期我尽量只想用一家模型，因为频繁切换会给策略执行带来摩擦。我花了差不多一周，想用gpt调出符合标准的设计产出，那一周我每天只睡三四个小时，也烧掉了大量 token，仍然看不到效果。后来实在受不了了，把同样的策略交给 Claude，它没用多少解释，就产出了远比gpt合我口味的页面。所以现在的分工是：gpt5.5负责编排、分析和拆解任务，opus4.7负责设计和网站产出。

## 6.交付——每个视频都跳过的部分

去看那些"AI一键赚钱"的视频，你会发现它们全在讲怎么找客户（虽然这一步也是割韭菜的），没人讲怎么交付。

我的交付，是一个真正上线部署好的网站，包含两次修改。根据需求和预算，还可以增加图片升级、预订功能、点餐功能，以及一个可以自己编辑的后台等。Cloudfare的免费版本完全可以覆盖商家需求。

现在一个交付大概需要我亲手投入两三个小时（也是通过claude完成搭建，deepseek负责部署）。起步阶段一单要花五个小时以上，有时接近一整天。两三个小时这个数字之所以存在，是几个月积累下来的demo、模板、踩过的坑和不断优化换来的。

还有一条原则。这个生意赚的是信息差的钱，但不代表我是骗子。虽然大部分是一锤子买卖，但我希望交出去的是一个合格的产品，最好是超出对方预期的产品。客户付了钱，网站就得配得上这个价格。

## 7.说说数字

定价：一个网站600-1500镑（800-1800刀），视需求大小而定。在英国和欧美，本地的代理公司做一个很基础的网站往往开口就要1500镑以上往上，而 Wix、GoDaddy 这类平台还要按月一直收费。我的报价是一次性付清，之后没有任何持续费用。这笔账小生意的老板很快就能算明白。

增长：第一个月是混乱的，只有零星几单，大部分时间在边跑边修这套工作流。第二个月达到十单左右。大概从第三个月开始稳定在每月 20 到 30 单。最近的峰值，一个月 3 万英镑左右。

成本：基本就是一个Codex 5x订阅、一个 Claude 5x订阅，再加一点调用google map API 的费用，一单就全覆盖了。不需要员工和外包，我每天真正工作的时间也就两到三个小时，主要花在交付和人工审核上，但是需要不停的跨时区与客户沟通。

## 8.一件我没料到的事

我原以为自己提供的是经济价值：更多预订、更多客人、更多营收。可单子做多了之后我才发现，大约有一半的老板（特别是餐饮业和美业）在为情绪价值付费。

有一个很具体的场景：老板打开 demo，看见自己的logo、自己的菜、自己的好评，出现在一个精致的网站里。有些人会被这一瞬间打动，那种感觉我能理解，和一个设计师第一次拥有属于自己的个人网站一样，坚持的事情在那一刻突然变得真实、正式。他们或许不刚需一个网站，但谁能拒绝一个仅需几百块的，能和家人朋友“炫耀”的机会呢？

对有些客户来说ROI最重要；而对另一部分，说到底看重的是那份体面和骄傲，这一点在西方社会尤为明显。按我的经验大概是五五开，我没有计划过这件事，但这些反馈确实改变了我做 demo 的方式。

## 9.写在结尾

我看着雨后春笋般冒出的ai博主，无时不刻不想加入其中，但总是觉得自己懂的不够多，总是觉得差那么一点点。如今有了些可以分享的成果，回头看方知贩卖焦虑者之可鄙、妄想不劳而获者之可笑。

当下ai变现的内容，大部分是从没做过这个生意的人，把工具卖给永远不会去做的人。

我的立场是类似场景的ai变现门槛不高，毕竟一年前我也才听说过vibecoding这个词，但落地远没有一些视频里看起来那么简单，而且你完全没必要为任何课程付费。一个闭环是靠无数细节和错误才能堆起的，在这过程中ai就是最好的老师。
